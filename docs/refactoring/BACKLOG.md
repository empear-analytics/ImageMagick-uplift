# Backlog

Every MagickCore file, ranked by whether the oracle can protect a refactoring of it, then
by Code Health. Scores are the committed baseline
([`codehealth-baseline.json`](codehealth-baseline.json), 2026-09-29, `cs-mcp` 1.5.6,
`cs` 1.0.46); protection is the mutation results in [`MUTATION.md`](MUTATION.md).

- **Mutants reached**: the share of sampled mutants on lines some case executes.
- **Killed, executed lines**: of those, the share the oracle notices. A file's figure is
  from 40-100 sampled mutants, so treat differences of a few points as noise, and run the
  function's own mutants before refactoring anything near the line.

How the groups were drawn:

| Group | Rule |
| --- | --- |
| Ready | at least 80% killed on executed lines and at least 60% reached |
| Check per function | at least 70% killed: fine for some functions, not all |
| Needs cases | below that, or too little reached to judge |
| Not built here | X11, OpenCL, Windows and VMS code, and files this build compiles to nothing |

Update the **Status** column as work lands: `open`, `in progress`, the reached score
(e.g. `10.00`), or `plateau 8.7` with a note in the playbook's *Known plateaus*.

## Order of work

1. **Ready image-processing files first**, where a mistake is caught and cheap: `resize.c`,
   `compare.c`, `enhance.c`, `morphology.c`, `visual-effects.c`, `colorspace.c`,
   `statistic.c`, `threshold.c`, `segment.c`, `decorate.c`, `colormap.c`, and `shear.c`
   (just under the line at 80%). `resize.c` is the pilot: it has the deepest mutation
   analysis. Task files M01-M13 in [`tasks/`](tasks/) cover these, generated by
   `tools/make_task.py`.
2. **The other ready files** - `geometry.c`, `identify.c`, `channel.c` - once the process
   is proven.
3. **Check-per-function files**: before each function, run its mutants and close the gaps
   the survivors point at.
4. **Needs-cases files**: add cases first (the gaps are listed in `MUTATION.md`), measure
   again, then refactor. This includes the infrastructure files `cache.c`, `blob.c`,
   `image.c` and `property.c`: the oracle reaches them everywhere but checks little of
   what they do (see *The infrastructure files are the weak spot* in `MUTATION.md`).
5. **Not built here**: on the Linux or Windows machine, where these files compile.
